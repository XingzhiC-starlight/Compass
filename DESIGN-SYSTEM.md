# Compass design system

## DS §0 About this document

This document ratifies Compass's design choices: the units the interface is built from —
color, typography, shape, spacing, sizing, elevation, motion — and the rules for using them.
It is the design counterpart of the spec in `docs/spec/`, which ratifies behavior; the two
together are the only ratified documents. It describes what the stylesheets do today, as an
honest inventory, not an aspiration: a value listed here is ratified because it is in use, and
a value in use that is not listed here is a defect that `npm run docs:check` reports — for
the units the census tracks. The census reads every declaration in the three stylesheets
(shorthand and longhand spacing folded together), every inline style object in the TSX files
(`style={…}` attributes and `CSSProperties` constants), and the `<style>` block of
`public/privacy.html`; it inventories every custom property, every raw color, and the values
of font-size, font-weight, line-height, letter-spacing, border-radius, padding, margin, gap,
width, height, min/max sizes, box-shadow, transition, outline and opacity. Outside it: border
widths, transforms, and whether any component uses a selector.

- **Visual reference.** The register is the Headspace app's: soft rounded bubbles, a warm
  muted palette, a calm friendly aesthetic, generous whitespace — every visual decision should
  make a visit feel like orientation, not a performance review.
- **Sources.** `src/styles/styles.css` (tokens, dashboard, sidebar, auth controls),
  `src/styles/interview.css` (the `.setup` screen), `src/styles/landing.css` (the `.landing`
  page), the inline style objects in the auth screens and `App.tsx`, the project
  accent palette in `src/lib/db.ts`, and `public/privacy.html` (a standalone copy of the
  tokens). The tables marked `<!-- census: … -->` are generated by
  `node scripts/design-census.mjs --write`, and its token tables (§9.2, §9.3, §11) cite the
  `/* DS §… */` anchor comment nearest each definition. Those tables are generated inventory,
  not ratified prose: they are
  regenerated with the commit that changes the CSS; the prose around them, the ratified scales
  and the `D-n` rules are edited by hand in the same pull request.
- **IDs.** Section numbers (`DS §N`) are permanent and appended, never renumbered. Rules carry
  stable IDs `D1…` so changes and tests can cite them.
- **Changing a unit** — adding a token, widening a scale, retiring a literal — is a design
  change: it edits this document in the same commit as the CSS.

## DS §1 Rules

| ID | Rule |
|---|---|
| D1 | **Units only, in this lookup order.** For any visual change — background, border, text color, divider, hover, active, shadow, focus ring, disabled state, radius, spacing, size — search this document first, then the tokens in `styles.css`: (1) use an existing design token when it approximately achieves the effect; (2) else an existing component variable (§9); (3) else an existing semantic token; (4) only then a new token. Never a one-off value. |
| D2 | **A new unit** is placed in an existing family (primary scale, a module family, the spacing scale, the radius set…), follows that family's naming and tonal steps, is documented here with its semantic purpose and why the existing units fell short, and lands in the same commit as its first use. |
| D3 | **Coral is the Time accent only.** `--accent-time` and the coral family color Time-related information and Time controls (the clock, its bar, its card); never auth, navigation, general CTAs or generic focus. The active project and generic focus use the primary family; a selection inside a module uses that module's accent (§2.3). |
| D4 | **Every raw literal is sanctioned here or is a defect** — for the units the census tracks (§0). The color literals outside token definitions are enumerated in §2.7; the literal scales for type, radius, spacing, size, shadow, motion, focus outlines and opacity are the tables in §2–§9. `landing.css` keeps the literals of its design handoff on purpose: the card-label gray `#6d6d6d`, the white washes on the Thought card and the demo's hotspots, the segmented control's shadow, the radii 22, 26 and 14 px, and its letter-spacings. They appear in those tables and never become tokens. |
| D5 | **Numbers are text, not always-on inputs.** Numbers in the cards render as text, and those a person can change become an input only while being edited (I14); `tabular-nums` is applied only to Lexend metric fields (the hero, hours, days, percent, and the setup screen's number fields, which are always inputs). |
| D6 | **Fonts are self-hosted.** The nine faces in §3.1 load from `public/fonts/` with `font-display: swap`; the app and `public/privacy.html` share that one served copy. No third-party font hosts (the CSP keeps `font-src 'self'`, spec §17). |
| D7 | **Fluid landing, breakpoints only in the app.** `landing.css` has no width media queries; its type and grid scale with the viewport, and 768 px is the one breakpoint, applied in JavaScript by the demo. The app's breakpoints are the seven in §6.1: five in `interview.css` (1080, 940, 860, 620, 480 px), one in `styles.css` (520 px, the Settings popover) and one applied in JavaScript by the sign-in screen (480 px, the CAPTCHA's size). |
| D8 | **Motion is small and even.** Transitions use `ease` only, at 120–400 ms from the set in §8.1; there are no keyframe animations. `prefers-reduced-motion` is honored everywhere — `styles.css` turns every transition and animation off under it, `interview.css` and `landing.css` repeat that for their scopes — so the landing frames swap instantly. Fills and hovers move; nothing bounces. |
| D9 | **No red, no alarms.** Error and failure lines use a muted text color (`--text-muted`, or the setup screen's muted browns) and calm copy (spec §2, §7); progress that moves backward keeps its color. Nothing in the palette is a warning color. Empty states invite rather than apologize: an empty task list shows only "+ Add a task", and an empty Learning card says "Add something to learn"; never "You haven't added any tasks." |
| D10 | **Everything is a bubble.** Containers use the radius tokens — cards `--r-bubble`, pills and the auth fields `--r-pill`, the dashboard's boxed inputs `--r-input` — or the setup and landing radii in §4; smaller inner elements use the literal radii listed in §4.2. `border-radius: 0` appears only to flatten an underlined field or to reset an inherited radius on an inner element, and a zero corner inside a shorthand only to shape the landing's arch (`28px 28px 0 0`) and quarter-round (`100% 0 0 0`). |
| D11 | **Accent restraint.** A module's wash stays soft; its full-strength accent is reserved for the header dot, progress fills and slider, and interactive highlights, and its hairline edge is a faint tint of it — a bubble is never flooded with accent. Two buttons are filled with a full-strength accent whenever they show: the Commitment card's clock button (coral, D3) and the thought log's Group or Merge button (Task yellow). The check of a task, phase or learning item fills with its accent only once it is done. |

### DS §2.3 Selection and focus

The active project and generic focus use the primary family, not a module color: the active
project pill is `--primary-700` with white text and its accent dot lightened to
`rgba(255,255,255,0.7)`. A selection inside a module uses that module's accent: a selected
thought is washed in Task yellow, and a selected group is also edged in it.
Focus is drawn four ways today: the dashboard controls' 3 px `box-shadow` ring in
`color-mix(in srgb, var(--primary-500) 28–34%, transparent)`; the Settings popover's 2 px
`outline` in a 55% mix of the same; the landing hotspots' 2 px solid `--primary-600` outline;
the setup screen's calm ring `--focus-ring-primary-soft`. The Commitment clock's coral ring is
Time's own (D3). Five rules still key on `:focus` rather than `:focus-visible`: `.auth-input`, the setup
title input (two selectors), every setup `input`, and the setup level select. The outlines in
use:

## DS §6 Sizing

### DS §6.1 Structural sizes

- The app is one centered card of `80vw × 80vh` on the page background; inside it a
  `220px 1fr` grid holds the sidebar and the dashboard; the upper row is three equal columns
  (`1fr 1fr 1fr`) and the dashboard rows are `auto minmax(0, 1fr)` in summary and
  `minmax(0, 1.7fr) minmax(0, 1fr)` in depth.
- The setup screen is a `--setup-form-width` (720 px) form beside a `--setup-rail-width`
  (180 px) rail with a `--setup-rail-gap` of 56 px. Its breakpoints: at 1080 px the rail
  narrows to 156 px and the gap to 40 px; at 940 px the form narrows to 680 px and the rail to
  140 px; at 860 px the rail folds under the form; 620 px and 480 px tighten the rows and type
  further. The repeat rows are sized by `--setup-row-*` so the hover shell covers grip, fields
  and delete button exactly (§9.2).
- The Settings popover is absolutely placed beside its button and moves to a narrower
  placement at 520 px and below (`styles.css`).
- The auth card's CAPTCHA is Cloudflare's widget, whose box and colors cannot be styled; its
  size and theme are options. It takes the normal box (300 × 65 px) on a viewport 480 px wide
  or wider and the compact box (150 × 140 px) below that, decided in JavaScript at the moment
  the widget appears (`src/auth/captchaSize.ts`), so the 460 px auth card keeps equal margins
  on a phone. 480 px is the interview's narrowest breakpoint reused (D1): the normal box needs
  about 437 px of viewport to fit inside the resend panel. The widget is always asked for its
  light theme. In the resend panel it carries a 10 px bottom margin, equal to the margin of
  the line above it.
- The landing column is `max-width: 1180px` with 32 px side padding; the demo stage keeps a
  `2952 / 1775` aspect ratio; the category cards flow in `auto-fit, minmax(260px, 1fr)` and
  the task bubble's inner grid in `auto-fit, minmax(280px, 1fr)`.
- The Commitment sparkline draws bars up to 36 px tall from a 49-day series.

  `.glance-cue` a bare button; `.companion-thought`, which boxes the thought input with the form material
  (§2.5) and `--r-input`, its border turning `--primary-600` in focus (§2.3);
  `.companion-body`, which turns off the page body's centering.
- **The sidebar's button.** `.sidebar-companion` shares every rule of `.sidebar-settings`,

  style. The companion's last line, "Open Compass", is `.sidebar-companion` too, centered

## DS §10 Design debt

Facts about the current inventory that a design change would address (the design-system
overhaul in `docs/ideas.md`). Nothing here is a rule.

- Type sizes, weights, line heights and tracking are literals: 21 sizes, 13 line heights.
- Radii, paddings, margins, gaps, widths and heights are mostly literals; the spacing tokens
  cover a minority of declarations.
- Shadows: literal box-shadows beside the three tokens; the warm shadow family is spelled out
  in `rgba(58, 42, 20, …)` in several places, and `App.tsx`'s save note carries the one black
  shadow.
- Inverse text is spelled three ways — `#fff`, `var(--surface)` and `var(--primary-25)` — for
  the same role (white on a filled control).
- Black-alpha and white-alpha overlays are a long tail (§2.7) rather than a small semantic set.
- The Settings popover uses eight blue-gray literals outside the primary family.
- The auth screens keep layout in inline style objects.
- `public/privacy.html` carries its own copy of the tokens (and a `--muted: #6f6f6f`) and must
  be edited by hand when the primary family changes.

## DS §12 Themes

The dashboard has two looks, chosen in Settings (spec §14). Classic is the dashboard as the
sections above describe it: each card on its module's wash, the sidebar flat on the page.
Sand is the same dashboard on the sand family alone. A theme is one block of overrides of
existing tokens in `styles.css` (anchor `DS §12`), under `:root[data-theme="sand"]`, and one
rule for the sidebar. It adds no token, and no component has a themed variant: accents, inks,
type, shape, spacing, elevation and motion are shared by both looks.

| Unit | Classic | Sand |
|---|---|---|
| The page, `--bg` | `--primary-300` | `--primary-200` |
| The four washes, `--bg-time`, `--bg-timeline`, `--bg-learning`, `--bg-task` | the module washes (§2.2) | `--primary-100`, one wash for all four |
| The four edges, `--edge-time`, `--edge-timeline`, `--edge-learning`, `--edge-task` | the accent-tinted hairlines (§2.2) | `color-mix(in srgb, var(--primary-300) 60%, var(--primary-100))`, one sand hairline for all four |
| The sidebar | `--sidebar-bg`, no border, no shadow | `--sidebar-bg`, with the bubble's border `rgba(0,0,0,0.04)` and `--shadow-rest`; its padding gives up the border's 1 px on each side |

- **The page is one step lighter and the cards one step lighter still**, so a card is told
  from the page by its shadow and its hairline, not by a hue. The sidebar is already
  `--primary-100`, the cards' surface in Sand, so it takes the bubble's border and resting
  shadow and reads as one more card. Its padding is 1 px less on each side, the border's
  width, so nothing inside it moves or truncates differently between the two looks.
- **The edge is a mix**, the form material's idiom (§2.5), between `--primary-200` and
  `--primary-300`: `--primary-200` is the page in Sand, so a hairline in it would vanish
  against the page, and `--primary-300` is heavy enough to read as a drawn outline.
- **Module color in Sand is the accent only** (D11): the header dots, the progress fills, the
  slider, the checks, the inks and the accent-alpha state colors (§2.2). The task panel's
  active toggle fills with `--bg-task`, so it is sand too.
- **Only the dashboard is themed.** The mark is on the document root only while the dashboard
  shows (spec §14), so the landing page's demo cards keep the module washes, and the auth
  screens, the setup and the archive screen are the same under both.
- **The Theme control in Settings** is the task panel's toggle recipe (`.panel-toggle`) with
  words in place of glyphs: a `rgba(0,0,0,0.05)` track 28 px high with 3 px of padding, 22 px
  buttons, and the pressed one lifted by `0 1px 3px rgba(58,42,20,0.12)`. The pressed button
  fills with `--surface`, not Task yellow, because Settings belongs to no module (§2.3); its
  text uses two of the Settings grays, `#4D5870` at rest and `#2F3338` pressed or hovered.
